# Chest Boosts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a CRUD management page for chest boost periods (which animal is boosted in Epic/Retro/Legendary chests during a date range) under `/game/chests`.

**Architecture:** New `ChestBoost` Prisma model linked to the existing `Animal` model via FK; server-only service layer; standard Next.js App Router pattern (Server page → Client wrapper → Content component with Zustand store); shared `ChestBoostForm` used for both create and edit.

**Tech Stack:** Next.js 16 App Router, Prisma 6 + MySQL, Zustand, Styled Components, next-intl, Vitest

**Spec:** `docs/superpowers/specs/2026-10-28-chest-boosts-design.md`

## Global Constraints

- Never install new npm packages without explicit user approval.
- Always use functional components with Styled Components; no Tailwind.
- All Prisma queries live in `src/service/` only.
- Add i18n keys to all 6 locales: `de`, `en`, `da`, `nl`, `es`, `fr`.
- Auth pattern: check `isMayor` first (→ 403 MayorReadonly), then `hasMinimumRole(session, "Director")` (→ 403 unauthorized).
- API routes always export `export const dynamic = "force-dynamic"`.
- Route params are `Promise<{ ... }>` — always `await params`.
- Test language: German (matching existing test files).

## Review Focus

- **startDate ≥ endDate:** Form should prevent/reject invalid date ranges; API should validate.
- **animalId references a deleted animal:** The overview query uses a JOIN; test that deleted animals don't cause a crash (Prisma `onDelete` behavior).
- **Filter by year across year boundary:** e.g. a boost starting Dec 2025 ending Jan 2026 — `getFullYear(startDate)` determines the year bucket.
- **Unknown ChestType value in DB:** If a future value is added to the enum before the app is deployed, the filter select should not crash.
- **Empty animal list in form:** If the DB has no animals, the searchable select should render an empty state, not crash.

These are tested in Tasks 3 (filter), 5 (frontend service error paths), and noted for manual QA on Tasks 9 and 10.

**Interfaces:**

- [ ] **Step 1: Create `src/store/useChestBoostStore.ts`**

  Follow the `useAnimalStore` pattern exactly. State interface:

  ```typescript
  interface ChestBoostState {
    allBoosts: ChestBoostListItem[];
    currentItems: ChestBoostListItem[];
    filteredCount: number;

    searchTerm: string;
    selectedChestType: ChestType | null;
    selectedYear: number | null;
    currentPage: number;
    itemsPerPage: number;

    setInitialBoosts: (boosts: ChestBoostListItem[]) => void;
    setSearchTerm: (term: string) => void;
    setSelectedChestType: (type: ChestType | null) => void;
    setSelectedYear: (year: number | null) => void;
    resetFilters: () => void;
    nextPage: () => void;
    prevPage: () => void;
    setPage: (page: number) => void;

    saveBoost: (data: ChestBoostCreateInput, id?: number) => Promise<number | false>;
    deleteBoost: (id: number, t: any, tCommon: any) => Promise<boolean>;
  }
  ```

  `runPipeline` function: `filterChestBoosts(all, state) → sortChestBoosts → paginateChestBoosts(…, state.currentPage, state.itemsPerPage)`. Updates `currentItems` and `filteredCount`.

  `setInitialBoosts`: sets `allBoosts`, calls `runPipeline`.

  Each filter setter resets `currentPage` to 1, calls `runPipeline`.

  `saveBoost(data, id?)`: calls `updateChestBoostOnClient(id, data)` if `id` provided, else `createChestBoostOnClient(data)`. On success: refetch via `GET /api/chest-boosts?locale=de` and call `setInitialBoosts`. On error: call `showErrorToast`. Return `id` on success, `false` on error.

  `deleteBoost(id, t, tCommon)`: call `confirmDeleteDialog(t("delete_confirm"), tCommon)`. If confirmed: call `deleteChestBoostOnClient(id)`. On success: remove from `allBoosts`, call `runPipeline`, `showSuccessToast`. Return `true`/`false`.

  `itemsPerPage` default: 20.
